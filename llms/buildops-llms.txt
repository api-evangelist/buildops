# BuildOps

> BuildOps is an AI-native, all-in-one commercial contractor management platform for
> multi-trade service and construction companies, unifying project management, service
> operations, dispatch and scheduling, financials and invoicing, and sales/CRM. BuildOps
> operates a public Dev Center and states that its platform exposes a public REST API with
> webhook callbacks — but that API documentation is marked "Invite Required" and is not
> reachable without a customer relationship, so no machine-readable contract (OpenAPI,
> AsyncAPI, GraphQL SDL, Postman collection) is published anywhere.

## API surface

- [BuildOps Public API](https://developer.buildops.com/docs/buildops-public-api): REST API
  with webhook callbacks, named by the BuildOps Dev Center. **Invite required** — the
  documentation page returns HTTP 404 to the public. The production host is
  `https://public-api.live.buildops.com` (live; root and `/health` return `OK!`), but it
  serves no specification on any conventional path. No endpoints, no authentication model
  and no rate limits are published.

The contracts exist and are auth-gated rather than absent. Probed 2026-08-10:
`https://api.core.live.buildops.com/v3/api-docs` returns **401** ("Authorization token
isn't provided") — a springdoc-generated OpenAPI is being served behind auth, since a
missing spec would 404. `https://graphql.live.buildops.com/graphql` refuses an
introspection POST with **403** ("Your authorization token is invalid"). Any agent or
integrator therefore needs a BuildOps customer relationship before it can read the
contract at all.
- [BuildOps Data Dictionary](https://developer.buildops.com/docs/data-dictionary/4b402d5ab3edd-build-ops-datasets):
  the only public project in the Dev Center. Documents the datasets BuildOps offers via the
  Dashboard module and a Snowflake private share. Articles only — zero API nodes, zero
  operations.

## Not published

The following were probed on 2026-08-10 and are genuinely absent from BuildOps' public
surface:

- OpenAPI / Swagger — no spec served publicly at any BuildOps host or docs path (one is
  generated behind auth at api.core.live.buildops.com/v3/api-docs)
- AsyncAPI — none, despite webhook callbacks being advertised
- GraphQL SDL — a GraphQL endpoint exists at graphql.live.buildops.com/graphql but
  introspection is gated (403)
- MCP server — none for the BuildOps API
- A2A agent card — /.well-known/agent-card.json and /.well-known/agent.json miss on every host
- /.well-known/security.txt, openid-configuration, oauth-authorization-server, api-catalog — none
- Status page — the widget in the Dev Center belongs to Stoplight, not BuildOps
- Public changelog, SDKs, CLI, sandbox, published rate limits, published plans
